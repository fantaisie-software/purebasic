@Library Dialog

@Overview
  Die Dialog Befehlsbibliothek ermöglicht das einfache Erstellen komplexer Benutzeroberflächen (GUI) -
  basierend auf einer @LibraryLink "xml" "XML"-Definition. Sie verfügt über ein automatisches
  @LibraryLink "gadget" "Gadget"-Layout, was sehr nützlich beim Erstellen von Oberflächen ist, die
  auf verschiedenen Betriebssystemen laufen oder mit verschiedenen @LibraryLink "font" "Zeichensatz"-Größen
  arbeiten sollen.
  @LineBreak
  @LineBreak
  Die XML-Definition kann @LibraryLink "file" "Datei"-basierend sein, oder mit Hilfe der 
  @LibraryLink "xml" "XML"-Bibliothek während der Laufzeit ("on the fly") im @LibraryLink "memory" "Speicher"
  erstellt werden.
  @LineBreak
  @LineBreak
  Eine Liste aller unterstützten Schlüsselwörter und Attribute dieser Bibliothek finden Sie @Link "OpenXMLDialog" "hier".

@CommandList

@ExampleFile All Dialog.pb

@SupportedOS

;--------------------------------------------------------------------------------------------------------

@Function Ergebnis = CreateDialog(#Dialog)

@Description
  Erstellt einen neuen nicht initialisierten Dialog. Um den Dialog zu initialisieren,
  verwenden Sie @@OpenXMLDialog (um ihn als eigenes Fenster zu öffnen) oder @@XmlDialogGadget
  (um ihn als in ein bestehendes Fenster eingebettetes Gadget zu erstellen).

@Parameter "#Dialog"
  Eine Zahl zum Identifizieren des neuen Dialogs. @ReferenceLink "purebasic_objects" "#PB_Any" kann verwendet
  werden, um diese Zahl automatisch zu generieren.

@ReturnValue
  Gibt einen Wert ungleich Null zurück, wenn der Dialog erfolgreich erstellt wurde, oder Null wenn nicht.
  Wenn @#PB_Any als #Dialog Parameter verwendet wurde, dann wird im Erfolgsfall die automatisch generierte
  Nummer zurückgegeben.

@SeeAlso
  @@OpenXMLDialog, @@XmlDialogGadget, @@FreeDialog
  
@SupportedOS

;--------------------------------------------------------------------------------------------------------

@Function Ergebnis$ = DialogError(#Dialog)

@Description
  Gibt die letzte Fehlernachricht (in Englisch) zurück, um nach einem @@OpenXMLDialog oder @@XmlDialogGadget
  weitere Informationen über einen Fehler bei der Dialog-Erstellung zu erhalten.

@Parameter "#Dialog"
  Der zu verwendende Dialog.

@ReturnValue
  Gibt die Fehlernachricht zurück. Wenn keine weiteren Informationen verfügbar sind, dann kann die
  Fehlernachricht leer sein.

@SeeAlso
  @@CreateDialog, @@OpenXMLDialog, @@XmlDialogGadget

@SupportedOS

@Function Ergebnis = DialogGadget(#Dialog, Name$)

@Description
  Gibt die @LibraryLink "gadget" "Gadget"-Nummer des Gadgets mit dem angegebenen Namen zurück.

@Parameter "#Dialog"
  Der zu verwendende Dialog.

@Parameter "Name$"
  Der Name des Gadgets, wie in der XML-Datei angegeben (unter Verwendung des 'name' Attributs).

@ReturnValue
  Gibt die zum angegebenen Gadget-Namen gehörende Gadget-Nummer zurück, oder -1 wenn das Gadget
  im Dialog nicht gefunden wurde. @LineBreak
  Bei einem mit @@XmlDialogGadget erstellten Dialog kann das Root-Gadget selbst auch auf diese
  Weise abgerufen werden, indem dem Root <window> Element im XML ein 'name'-Attribut zugewiesen wird.

@SeeAlso
  @@CreateDialog, @@OpenXMLDialog, @@XmlDialogGadget

@Description

@Parameter "#Dialog"
  Der zu verwendende Dialog.

@ReturnValue
  Gibt die Fenster-Nummer des angegebenen Dialogs zurück oder -1, wenn der Dialog mit @@XmlDialogGadget
  anstelle von @@OpenXMLDialog erstellt wurde, da er in diesem Fall über kein eigenes Fenster verfügt.  

@SeeAlso
  @@CreateDialog, @@OpenXMLDialog, @@XmlDialogGadget

@Function DialogLanguage(Map())

@Description
  Legt die Texte fest, die vom 'lang'-Attribut der Dialog-XML-Elemente verwendet werden, und aktualisiert
  alle bereits geöffneten Dialoge. Dies ermöglicht es, einen Dialog auf einfache Weise zu übersetzen oder
  dessen Sprache während der Programmausführung zu ändern.
@LineBreak
@LineBreak
  Im XML zeigt ein Element mit einem 'lang'-Attribut (z.B. lang="Main:Ok") den Text an, der in der Map
  unter diesem Schlüssel hinterlegt ist. Verfügt das Element zusätzlich über ein 'text'-Attribut, so wird
  dessen Inhalt an den aus der Map stammenden Text angehängt (nützlich für einen festen Suffix, wie etwa
  ":"). Wird der Schlüssel in der Map nicht gefunden, so wird der Schlüssel selbst angezeigt; auf diese
  Weise lassen sich fehlende Übersetzungen leicht erkennen.
@LineBreak
@LineBreak
  Das 'lang'-Attribut wird vom Titel des <window>-Fensters, dem Text von Gadgets, den <tab>-Elementen
  innerhalb eines Panels sowie den <item>- und <column>-Elementen unterstützt.

@Parameter "Map()"
  Eine String-Map (Map Name$()) mit den Sprachtexten. Die Schlüssel der Map entsprechen den Werten, die
  in den 'lang'-Attributen verwendet werden; sie sind unabhängig von der Groß-/Kleinschreibung. Die Map
  wird kopiert, sodass sie nach dem Aufruf geändert oder freigegeben werden kann. Eine leere Map entfernt
  alle Sprachtexte.

@NoReturnValue

@Remarks
  Bei einer Sprachaktualisierung werden nur die Texte geändert, die aus einem 'lang'-Attribut stammen;
  vom Benutzer geänderte Inhalte (wie etwa der Text eines @@StringGadget) bleiben hingegen erhalten.
  Da die neuen Texte eine andere Größe aufweisen können, werden geöffnete Dialoge – ähnlich wie bei
  @@RefreshDialog – neu berechnet. Auch Dialoge, die nach dem Aufruf geöffnet werden, verwenden die
  aktuelle Sprache.

@Example
@Code
  #Dialog = 0
  #Xml = 0

  XML$ = "<window name='test' lang='Main:Title' flags='#PB_Window_ScreenCentered | #PB_Window_SystemMenu'>" +
         "  <vbox>" +
         "    <text lang='Main:Name' text=':'/>" +
         "    <string/>" +
         "    <combobox name='language'>" +
         "      <item text='English'/>" +
         "      <item text='Français'/>" +
         "    </combobox>" +
         "  </vbox>" +
         "</window>"

  NewMap English$()
  English$("Main:Title") = "Welcome"
  English$("Main:Name")  = "Your name"

  NewMap French$()
  French$("Main:Title") = "Bienvenue"
  French$("Main:Name")  = "Votre nom"

  DialogLanguage(English$())

  If ParseXML(#Xml, XML$) And XMLStatus(#Xml) = #PB_XML_Success
    If CreateDialog(#Dialog) And OpenXMLDialog(#Dialog, #Xml, "test")
      SetGadgetState(DialogGadget(#Dialog, "language"), 0)

      Repeat
        Event = WaitWindowEvent()
        If Event = #PB_Event_Gadget And EventGadget() = DialogGadget(#Dialog, "language")
          If GetGadgetState(EventGadget()) = 1
            DialogLanguage(French$())
          Else
            DialogLanguage(English$())
          EndIf
        EndIf
      Until Event = #PB_Event_CloseWindow
    Else
      Debug "Dialog error: " + DialogError(#Dialog)
    EndIf
  Else
    Debug "XML error: " + XMLError(#Xml) + " (Line: " + XMLErrorLine(#Xml) + ")"
  EndIf
@EndCode

@SeeAlso
  @@OpenXMLDialog, @@RefreshDialog

@SupportedOS

@Function Ergebnis = FoldDialogElement(#Dialog, Name$, Status)

@Description
  Klappt das angegebene Dialogelement ein oder aus. Ein eingeklapptes Element sowie alle seine
  untergeordneten Elemente werden ausgeblendet und beanspruchen keinen Platz im Layout. Dies entspricht
  dem XML-Attribut 'folded', jedoch zur Laufzeit.
@LineBreak
@LineBreak
  Die Größe des Dialogfensters passt sich an die Größe des Elements an: es verkleinert sich, wenn das
  Element eingeklappt wird, und vergrößert sich, wenn es ausgeklappt wird. Eine zusätzliche
  Größenfestlegung durch das Programm oder den Benutzer bleibt dabei erhalten. Ein maximiertes
  Fenster behält seine Größe bei, während die übrigen Elemente den freien Platz nutzen. Der Dialog wird
  daraufhin – ähnlich wie bei @@RefreshDialog – neu berechnet.

@Parameter "#Dialog"
  Der zu verwendende Dialog.

@Parameter "Name$"
  Das 'name'-Attribut des Elements, das ein- oder ausgeklappt werden soll. Es kann jedes beliebige
  Element verwendet werden, einschließlich Layout-Elementen wie <vbox> oder <gridbox> (nicht nur
  Gadgets).

@Parameter "Status"
  @#True, um das Element einzuklappen; @#False, um es auszuklappen.

@ReturnValue
  Gibt einen Wert ungleich null zurück, falls das Element gefunden wurde, andernfalls null.

@Remarks
  Wenn ein Element aufgeklappt wird, werden seine untergeordneten Elemente nur dann wieder angezeigt,
  wenn keines seiner übergeordneten Elemente noch zugeklappt ist.
  Untergeordnete Elemente, die selbst zugeklappt sind, bleiben zugeklappt.

@Example
@Code
  #Dialog = 0
  #Xml = 0

  XML$ = "<window name='test' flags='#PB_Window_ScreenCentered | #PB_Window_SystemMenu'>" +
         "  <vbox expand='no'>" +
         "    <checkbox name='more' text='Show the options'/>" +
         "    <frame name='options' text='Options' folded='yes'>" +
         "      <vbox>" +
         "        <checkbox text='Option 1'/>" +
         "        <checkbox text='Option 2'/>" +
         "      </vbox>" +
         "    </frame>" +
         "    <button text='OK'/>" +
         "  </vbox>" +
         "</window>"

  If ParseXML(#Xml, XML$) And XMLStatus(#Xml) = #PB_XML_Success
    If CreateDialog(#Dialog) And OpenXMLDialog(#Dialog, #Xml, "test")
      Repeat
        Event = WaitWindowEvent()
        If Event = #PB_Event_Gadget And EventGadget() = DialogGadget(#Dialog, "more")
          FoldDialogElement(#Dialog, "options", 1 - GetGadgetState(EventGadget()))
        EndIf
      Until Event = #PB_Event_CloseWindow
    Else
      Debug "Dialog error: " + DialogError(#Dialog)
    EndIf
  Else
    Debug "XML error: " + XMLError(#Xml) + " (Line: " + XMLErrorLine(#Xml) + ")"
  EndIf
@EndCode

@SeeAlso
  @@OpenXMLDialog, @@RefreshDialog

@SupportedOS

@Function FreeDialog(#Dialog)

@Description
  Gibt den angegebenen Dialog und den zugehörigen Speicher frei. Falls das Dialogfenster noch
  geöffnet war, wird es automatisch geschlossen. Bei einem mit @@XmlDialogGadget erstellten Dialog
  wird stattdessen das zugehörige Gadget freigegeben (das Fenster, das es enthält, bleibt unverändert).

@Parameter "#Dialog"
  Der freizugebende Dialog. Wenn @#PB_All angegeben wird, dann werden alle verbliebenen
  Dialoge freigegeben.

@NoReturnValue

@Remarks
  Alle verbliebenen Dialoge werden automatisch freigegeben, wenn das Programm endet.
  
@SeeAlso
  @@CreateDialog

@SupportedOS

;--------------------------------------------------------------------------------------------------------

@Function Ergebnis = IsDialog(#Dialog)

@Description
  Überprüft, ob die angegebene Dialog-Nummer ein gültiger Dialog ist.

@Parameter "#Dialog"
  Der zu testende Dialog.

@ReturnValue
  Gibt einen Wert ungleich Null zurück, wenn #Dialog ein gültiger Dialog ist, und Null wenn nicht.

@Remarks
  Diese Funktion ist "kugelsicher" und kann mit jedem Wert verwendet werden.
  Dies ist der korrekte Weg, um sicherzustellen, dass ein Dialog fertig zur Verwendung ist.

@SeeAlso
  @@CreateDialog

@Function Ergebnis = OpenXMLDialog(#Dialog, #XML, Name$ [, x, y [, Breite, Höhe [, ParentID]]])

@Description
  Öffnet den angegebenen Dialog und zeigt diesen auf dem Bildschirm an.
  Um auf die @LibraryLink "gadget" "Gadgets" des Dialogs zurückzugreifen, verwenden Sie @@DialogGadget.
  Um die @LibraryLink "window" "Fenster"-Nummer dieses Dialogs zu erhalten, verwenden Sie @@DialogWindow. 
@LineBreak
@LineBreak
  @@UseDialogScintillaGadget, @@UseDialogOpenGLGadget, @@UseDialogWebGadget und @@UseDialogWebViewGadget
  können verwendet werden, um die Unterstützung für diese Gadgets in der Dialogbibliothek zu aktivieren.
  Sie sind standardmäßig nicht aktiviert, um den "Footprint" (Platzbedarf) der Dialogbibliothek zu verringern.

@Parameter "#Dialog"
  Der zu verwendende Dialog. Dieser muss zuvor mittels @@CreateDialog erstellt werden.

@Parameter "#XML"
  Der zu verwendende @LibraryLink "xml" "XML"-Datensatz. Dieser muss zuvor mittels @@LoadXML, @@CreateXML, @@CatchXML
  oder @@ParseXML erstellt werden. Das bedeutet, es ist möglich, Dialoge während der Laufzeit "on the
  fly") mittels @@CreateXML, @@CatchXML oder @@ParseXML zu erstellen.
  @LineBreak
  Siehe unten für die unterstützten XML-Attribute. Beim Einbinden von XML im Quellcode kann es
  einfacher sein, im XML einfache Anführungszeichen (Apostrophe) für die Attribute zu nutzen
  (was absolut zulässiger XML-Syntax ist).

@Parameter "Name$"
  Der Name des zu öffnenden Dialogs. Eine XML-Datei kann mehrere definierte Dialoge beinhalten.

@OptionalParameter "x, y"
  Die x, y Koordinaten (in Pixel) des #Dialogs. Ist einer dieser Werte @#PB_Ignore, so wird der Dialog auf dem
  Bildschirm zentriert (oder auf seinem übergeordneten Fenster, falls im XML das Flag @#PB_Window_WindowCentered
  angegeben ist).

@OptionalParameter "Breite, Höhe"
  Die Größe (in Pixel) des #Dialogs. Ist die hier angegebene Größe kleiner als die benötigte Größe, wie sie im XML-Datensatz definiert
  wurde (nach der Layout-Kalkulation), dann wird die benötigte Größe verwendet. Wird dieser Parameter weggelassen,
  dann wird die Größe des Dialogs der kleinsten benötigten Größe entsprechen.

@OptionalParameter "ParentID"
  Die ID des übergeordneten Fensters. Eine gültige Fenster-ID kann mittels @@WindowID abgerufen werden.

@ReturnValue
  Gibt einen Wert ungleich Null zurück, wenn der Dialog erfolgreich geöffnet wurde, andernfalls Null.
  Um weitere Informationen über einen aufgetretenen Fehler zu erhalten, verwenden Sie @@DialogError.

@Remarks
  
@FixedFont
----------------------------------------------------------------
   Dialog XML-Format
----------------------------------------------------------------

  I. Allgemeine Attribute
  -----------------------

  width     - positiver Integerwert oder 0 (Standard="0") (legt die "Minimal-Größe" eines Gadgets fest)
  height      oder "ignore": das Objekt fordert keine bestimmte Breite/Höhe an und bewirkt daher keine
              Vergrößerung seines übergeordneten Elements (es erhält die vom Layout vorgegebene Größe).

  id        – #Nummer (ID) für ein Gadget oder ein Fenster (Standard ist #PB_Any, wenn nicht angegeben).
              Es kann sich um eine Laufzeitkonstante oder einen Ausdruck mit Laufzeitkonstanten handeln,
			  z.B. "#Gadget_First + 1" (siehe <compiler> unten für die unterstützten Operatoren).
  name      – ein String, der das Objekt identifiziert (hauptsächlich für @@DialogGadget, Groß-/Kleinschreibung
              wird nicht beachtet) (Standard="")
  text      - Text-String für das Objekt (Standard="")
  lang      – Sprachschlüssel des Textes, z.B. "Main:Ok". Der Text wird aus der mittels @@DialogLanguage
              festgelegten Map abgerufen; ein gegebenenfalls vorhandenes 'text'-Attribut wird daran angehängt.
              Ist der Schlüssel nicht in der Map enthalten, wird der Schlüssel selbst angezeigt.

  folded    – wenn auf "yes" gesetzt, werden das Objekt sowie alle zugehörigen untergeordneten Elemente
              ausgeblendet und beanspruchen keinen Platz im Layout (Standard="no"). Funktioniert bei jedem
			  Element (Layout bzw. Gadget). Siehe @@FoldDialogElement, um diese Einstellung zur Laufzeit zu ändern.

  flags     - Gadget/Window Flags in der Form "@#PB_Window_Borderless | @#PB_Window_ScreenCentered"  (Standard="")

  min       - Minimum-Wert
  max       - Maximum-Wert
  value     - aktueller Wert

  invisible - wenn auf "yes" gesetzt, wird das Objekt unsichtbar erstellt (Standard="no")
  disabled  - wenn "yes", wird das Objekt deaktiviert erstellt (nur bei Gadgets) (Standard="no")

  colspan   - nur innerhalb des <gridbox> Elements, ermöglicht einem Element sich über mehrere Zeilen/Spalten zu erstrecken
  rowspan     (Standard="1")

  Alle diese Attribute sind optional.


  II. Grund-Element
  -----------------

  <window> für eine einzelne Fenster-Definition in der gleichen XML-Datei
  </window>
  
  oder 
    
  <dialogs> für mehrere Fenster-Definitionen in der gleichen XML-Datei
    <window name="FirstWindow">
    </window>
    <window name="SecondWindow">
    </window>
    ...
  </dialogs>

  <dialoggroup> wird als Alias für <dialogs> akzeptiert, und <window>-Elemente können in <compiler>-Blöcke eingebettet
  werden (siehe unten), um beispielsweise je nach Betriebssystem eine unterschiedliche Fensterdefinition auszuwählen.

  Das Root-Element <window> wird durch @@OpenXMLDialog als echtes Fenster geöffnet. Dasselbe XML-Dokument
  lässt sich stattdessen mittels @@XmlDialogGadget in ein Gadget (ein @@ContainerGadget) umwandeln – in diesem
  Fall werden sämtliche Attribute oder Flags, die spezifisch für Fenster sind und am Root-Element <window>
  definiert sein könnten (wie title, screencentered, systemmenu usw.), einfach ignoriert.

  III. Fenster-Element
  -------------------

  <window>
  </window>
  
  Akzeptierte Schlüsselwörter im XML:
  Alle üblichen Attribute und die folgenden:
  
  minwidth  = 'auto' oder ein numerischer Wert (= Mindestbreite)
  maxwidth  = 'auto' oder ein numerischer Wert (= Maximalbreite)
  minheight = 'auto' oder ein numerischer Wert (= Mindesthöhe)
  maxheight = 'auto' oder ein numerischer Wert (= Maximalhöhe)
  
  Dies ermöglicht die Festlegung der Fenstergrenzen. Wenn die Werte auf 'auto'
  gesetzt sind, dann wird die Größe abhängig vom Platzbedarf der beinhalteten
  Gadgets berechnet.
  
  forcesize = 'yes' (Standard) oder 'no'
              'yes' entspricht minwidth="auto" und minheight="auto", 'no' hebt die Mindestgröße auf.
  invisible = 'yes' erstellt das Fenster im unsichtbaren Zustand (entspricht dem Flag @#PB_Window_Invisible).


  - Erstellt ein neues Fenster.
  - Kann alle üblichen Attribute haben.
  - Entspricht einem "Ein-Element"-Container.
  - Wenn mehr als ein <window> Element vorhanden ist, dann wird das 'name' Attribut zu deren Identifizierung verwendet.
  - Alle GUI-Elemente können nur hierin platziert werden.
  
  
  IV. Layout-Elemente
  -------------------
  
  *****************************************************************
  hbox und vbox
  *****************************************************************

    Ordnet die Elemente horizontal oder vertikal. Kann eine beliebige
    Anzahl von "Kindern" (Unterbereiche, Gadgets...) enthalten.

    Akzeptierte Schlüsselwörter im XML:

    Alle gebräuchlichen Attribute und die folgenden:
  
    spacing   = der zwischen den eingefassten Gadgets ("Childs") hinzuzufügende Abstand (Standard=5)
  
    expand    = yes           - Elemente werden vergrößert, um den Platz auszufüllen (Standard)
                no            - nicht vergrößern, um den gesamten Platz auszufüllen
                equal         - gleich große Elemente erzwingen
                item:<number> - nur ein Element vergrößern, wenn Platz verfügbar ist
  
    align     = top/center/bottom - wird nur mit expand="no" für die vbox angewendet, 'top' (oben) ist der Standard
              = left/center/right - wird nur mit expand="no" für die hbox angewendet, 'left' (links) ist der Standard
                                  - Eine Verbindung von vbox und hbox erlaubt die komplexe Ausrichtung top/left/center/bottom/right.


  *****************************************************************
  gridbox 
  *****************************************************************
  
    Richtet die Elemente in einer Tabelle aus. Kann eine beliebige
    Anzahl von "Kindern" (Unterbereiche, Gadgets...) enthalten.
    
    Akzeptierte Schlüsselwörter im XML:

    Alle gebräuchlichen Attribute und die folgenden:
  
    columns = Anzahl der Spalten (Standard = 2)
  
    colspacing = der zwischen den Spalten/Zeilen hinzuzufügende Abstand (Standard = 5)
    rowspacing
  
    colexpand = yes           - Elemente werden vergrößert, um den Platz auszufüllen
    rowexpand   no            - nicht vergrößern, um den gesamten Platz auszufüllen
                equal         - gleich große Elemente erzwingen
                item:<number> - nur ein Element vergrößern, wenn Platz verfügbar ist
  
                für colexpand ist der Standard=yes, für rowexpand der Standard=no

    Alle Elemente ("Childs") in einer Tabelle ("gridbox") können diese Schlüssel haben:
  
    colspan = Anzahl der zu umfassenden Spalten (Standard = 1)
    rowspan = Anzahl der zu umfassenden Zeilen
  
  *****************************************************************
  multibox
  *****************************************************************

    Eine Box mit mehreren "Childs" (Bereichen) an der gleichen Position.
    Wird verwendet, um mehrere Container darin abzulegen und nur einen
    davon zur gleichen Zeit anzuzeigen. Kann eine beliebige Anzahl
    von "Kindern" (Unterbereiche, Gadgets...) enthalten.
    
    Akzeptierte Schlüsselwörter im XML:

    Alle gebräuchlichen Attribute.
    
  *****************************************************************
  singlebox
  *****************************************************************

    Eine Box mit nur einem "Child" (Bereich). Wird nur verwendet, um extra
    Abstands-/Ausrichtungseigenschaften zu einem "Child" hinzuzufügen.
    Es wird eine Box genannt (so wie alle virtuellen Container genannt werden).

    Akzeptierte Schlüsselwörter im XML:
    
    Alle gebräuchlichen Attribute und die folgenden:
  
    margin = Rand rings um den Inhalt (Standard = 10)
             kann eine einzelne Zahl (= alle Ränder), oder eine Kombination von
             top:<num>,left:<num>,right:<num>,bottom:<num>,vertical:<num>,horizontal:<num>
             für die Randangaben zu oben/links/rechts/unten/vertikal/horizontal sein.
             Beispiel: "vertical:5,left:10,right:0"
  
    expand = yes        - Element werden vergrößert, um den Platz auszufüllen (Standard)
             no         - keine Vergrößerung
             vertical   - vergrößert nur vertikal
             horizontal - vergrößert nur horizontal
  
    expandwidth  = max. Größe, auf die das "Child" (Element) vergrößert werden soll. Wenn die
    expandheight   angeforderte Größe größer als diese Einstellung ist, dann wird die
                   angeforderte Größe verwendet (d.h. der Inhalt wird nicht kleiner).
                   (Standard=0)
  
    align  = Kombination von top,left,bottom,right und center. (nur wirksam, wenn expand <> yes)
             Beispiel: "top,center" oder "top,left" (Standard) 
             
             
             
  V. Gadget-Elemente
  ------------------

  Alle gebräuchlichen XML-Attribute werden unterstützt. Um eine Ereignis-Prozedur direkt im
  XML-Datensatz zu verknüpfen, sind für die Gadgets die folgenden Attribute verfügbar:
  
    onevent      = EventProcedure() - allgemeine Ereignis-Verknüpfung, für alle Ereignis-Typen
    onchange     = EventProcedure() - #PB_EventType_Change Verknüpfung (nur für Gadgets, die diesen Ereignis-Typ unterstützen)
    onfocus      = EventProcedure() - #PB_EventType_Focus Verknüpfung (nur für Gadgets, die diesen Ereignis-Typ unterstützen)
    onlostfocus  = EventProcedure() - #PB_EventType_LostFocus Verknüpfung (nur für Gadgets, die diesen Ereignis-Typ unterstützen)
    onresize     = EventProcedure() - #PB_EventType_Resize binding Verknüpfung (nur für Gadgets, die diesen Ereignis-Typ unterstützen)
    ondragstart  = EventProcedure() - #PB_EventType_DragStart Verknüpfung (nur für Gadgets, die diesen Ereignis-Typ unterstützen)
    onrightclick = EventProcedure() - #PB_EventType_RightClick Verknüpfung (nur für Gadgets, die diesen Ereignis-Typ unterstützen)
    onleftclick  = EventProcedure() - #PB_EventType_LeftClick Verknüpfung (nur für Gadgets, die diesen Ereignis-Typ unterstützen)
    onrightdoubleclick = EventProcedure() - #PB_EventType_RightDoubleClick Verknüpfung (nur für Gadgets, die diesen Ereignis-Typ unterstützen)
    onleftdoubleclick  = EventProcedure() - #PB_EventType_LeftDoubleClick Verknüpfung (nur für Gadgets, die diesen Ereignis-Typ unterstützen)

  Die 'EventProcedure()' muss als 'Runtime' im Hauptcode deklariert werden, und muss sich an das BindEvent() Prozedur-Format
  halten. Hinter den Kulissen wird BindGadgetEvent() mit der angegebenen Prozedur aufgerufen.
  
  Unterstützte Gadgets:

  <button>
  <buttonimage>
  <calendar>
  <canvas>
  <checkbox>
  <combobox>
  <container> - Container mit nur einem Element
  <date>
  <editor>
  <explorercombo>
  <explorerlist>
  <explorertree> 
  <frame> - Container mit nur einem Element (nur mit Standardrändern verfügbar)
  <hyperlink>
  <ipaddress>
  <image>
  <listicon>
  <listview>
  <opengl> - UseDialogOpenGLGadget() muss aufgerufen werden, um die <opengl> Unterstützung zu aktivieren.
  <option group> - numerischer Wert - verwende die gleiche 'group' Nummer, um zusammengehörende @@OptionGadget zu erstellen.
  <panel> - kann nur <tab> Elemente enthalten
  <progressbar min max Wert>
  <scintilla> - der Callback bleibt leer. UseDialogScintillaGadget() muss aufgerufen werden, um die <scintilla> Unterstützung zu aktivieren.
  <scrollarea scrolling="vertical,horizontal oder both (Standard)" innerheight="Wert oder auto (Standard)" innerwidth="Wert oder auto (Standard)" step> - 
     Container mit nur einem Element, der Scrollwert 'step' bestimmt das Wachstumsverhalten. <scroll> wird als Alias akzeptiert.
  <scrollbar min max page Wert> - 'page' = Seitenlänge.
  <shortcutgadget> - ein @@ShortcutGadget. <shortcut> ohne 'key'-Attribute erstellt ebenfalls ein @@ShortcutGadget.
  <spin min max Wert>
  <splitter firstmin="Wert oder auto" secondmin> - muss 2 Unterelemente enthalten, daher ist es
     grundsätzlich ein 2-Element-Container, die Mindestgröße wird von den beinhalteten Gadgets bestimmt.
     Wenn "auto" angegeben wird, dann wird der Mindestwert die Mindestgräße des "Childs" sein.
  <string>
  <text>
  <trackbar min max Wert>
  <tree> - kann <item> beinhalten
  <web> - UseDialogWebGadget() muss aufgerufen werden, um die <web> Unterstützung zu aktivieren.
  <webview> - UseDialogWebViewGadget() muss aufgerufen werden, um die <webview> Unterstützung zu aktivieren.

  Gadget-bezogene Elemente:
  <tab> - Einzelner Elementcontainer für Panel-Registerkarten (Attribute 'text' und 'lang' werden unterstützt).

  <item> – Fügt ein Element zu einem übergeordneten <combobox>, <listview>, <tree> oder <listicon> Element hinzu.
           Unterstützte Attribute: 'text', 'lang' und 'sublevel' (nur für <tree>).
  <column> – Fügt eine Spalte zu seinem übergeordneten <listicon> oder <explorerlist> Element hinzu. Die Standardspalten
             des Gadgets werden entfernt, sobald die erste <column> hinzugefügt wird. Unterstützte Attribute: 'text',
			 'lang' und 'width'. Siehe das Beispiel "Elemente und Spalten" weiter unten.

  Spezielle Elemente:
  <empty> - ein leeres Element, nützlich um etwas Abstand zwischen den Gadgets zu haben, zum Beispiel für deren Ausrichtung an den Rändern.

  <shortcut key id> – Fügt dem Dialogfenster ein Tastenkürzel hinzu, analog zu @@AddKeyboardShortcut. Es beansprucht
                      keinen Platz im Layout und wird ausschließlich in Verbindung mit @@OpenXMLDialog unterstützt. 
            key – Die #PB_Shortcut Konstanten, die mittels "|" kombiniert werden können (z.B. "#PB_Shortcut_Control | #PB_Shortcut_S").
                  Auch Laufzeitkonstanten und numerische Werte sind zulässig.
            id  – Die Menü-Ereignisnummer, angegeben als Laufzeitkonstante oder numerischer Wert. Sie wird über @@EventMenu abgefragt. 
                  Siehe dazu das Beispiel "Tastenkürzel" weiter unten.

  <compiler if="expression"> ... <compilerelse/> ... </compiler>
           Schließt die enthaltenen Elemente nur dann ein, wenn der Ausdruck wahr ist; ist der Ausdruck falsch, werden
           stattdessen die Elemente nach <compilerelse/> einbezogen (<compilerelse/> ist optional). Dies kann an
           beliebiger Stelle im Dialog verwendet werden, auch um <window>-Elemente herum.
           Da das XML zur Laufzeit des Programms eingelesen wird, erfolgt die Auswertung des Ausdrucks ebenfalls zur
           Laufzeit, wenn der Dialog geöffnet wird.
           Der Ausdruck unterstützt:
             - Zahlen (dezimal oder hexadezimal mit vorangestelltem '$')
             - Konstanten, die im Programm mit 'Runtime' deklariert wurden (wie etwa das 'id'-Attribut)
             - Variablen, die im Programm mit 'Runtime' deklariert wurden
             - Defined(Name, #PB_Constant) zur Überprüfung, ob eine Runtime-Konstante existiert
             - #True, #False, #PB_Compiler_OS, #PB_OS_Windows, #PB_OS_Linux und #PB_OS_MacOS
             - die Operatoren ( ), unäres -, Not, *, /, +, -, =, <>, <, >, <=, >=, And, Or, Xor

           In XML muss das Zeichen '<' innerhalb eines Attributwerts als '&lt;' geschrieben werden (z.B. "#Value &lt;= 10").
           Eine Compiler-Konstante wie #PB_Compiler_Debugger kann verwendet werden, sofern sie im Programm mit 'Runtime'
           deklariert wurde. Siehe dazu das Beispiel "Compiler-Bedingungen" weiter unten.

@EndFixedFont

@Function Ergebnis = XmlDialogGadget(#Dialog, #XML, Name$ [, x, y [, Breite, Höhe]])

@Description
  Erstellt den angegebenen Dialog als Gadget (ein @@ContainerGadget), anstatt ihn – wie mittels
  @@OpenXMLDialog – als eigenständiges Fenster zu öffnen. Dies ermöglicht es, einen in XML
  definierten Dialog in ein bestehendes Fenster einzubetten, neben anderen Gadgets.
@LineBreak
@LineBreak
  Es verwendet exakt dasselbe XML-Format wie @@OpenXMLDialog (siehe dessen Dokumentation für die
  vollständige XML-Referenz) – dasselbe XML-Dokument lässt sich für beide Befehle nutzen: Das
  Root-Element <window> wird zum erstellten @@ContainerGadget, und etwaige Attribute oder Flags,
  die spezifisch für Fenster sind (title, screencentered, systemmenu, ...), werden einfach
  ignoriert.
@LineBreak
@LineBreak
  Das Gadget wird innerhalb des aktuell aktiven Fensters erstellt, genau wie @@ContainerGadget
  selbst; daher muss @@XmlDialogGadget aufgerufen werden, nachdem das Fenster, das es aufnehmen
  soll, geöffnet (oder mittels @@UseGadgetList ausgewählt) wurde.
@LineBreak
@LineBreak
  Um auf die Dialog-Gadgets zuzugreifen – einschließlich des Root-Gadgets selbst, verwenden Sie
  @@DialogGadget (weisen Sie dem Root-Element <window> im XML ein 'name'-Attribut zu, um darauf
  zugreifen zu können). Im Gegensatz zu einem mit @@OpenXMLDialog geöffneten Dialog gibt
  @@DialogWindow bei einem mit @@XmlDialogGadget erstellten Dialog -1 zurück, da dieser über
  kein eigenes Fenster verfügt.
@LineBreak
@LineBreak
  @@UseDialogScintillaGadget, @@UseDialogOpenGLGadget, @@UseDialogWebGadget und @@UseDialogWebViewGadget
  können verwendet werden, um die Unterstützung für diese Gadgets in der Dialog-Bibliothek zu aktivieren.
  Sie sind standardmäßig nicht aktiviert, um den Speicherbedarf der Dialog-Bibliothek gering zu halten.

@Parameter "#Dialog"
  Der zu verwendende Dialog. Er muss zuvor mit @@CreateDialog erstellt worden sein.

@Parameter "#XML"
  Das zu verwendende @LibraryLink "xml" "XML". Es muss zuvor mit @@LoadXML, @@CreateXML, @@CatchXML
  oder @@ParseXML erstellt worden sein.
  Siehe @@OpenXMLDialog für die unterstützten XML-Attribute.

@Parameter "Name$"
  Der Name des zu verwendenden Dialogs. In einer XML-Datei können mehrere Dialoge definiert sein.

@OptionalParameter "x, y"
  Die x, y Koordinaten (in Pixeln) des #Dialog-Gadgets, relativ zu seinem Container.

@OptionalParameter "Breite, Höhe"
  Die Größe (in Pixeln) des #Dialog-Gadgets. Ist die Größe kleiner als die im XML definierte
  erforderliche Größe (nach der Layout-Berechnung), so wird die erforderliche Größe verwendet.
  Wenn nicht angegeben, wird die Größe des Dialogs der minimal erforderlichen Größe entsprechen.

@ReturnValue
  Gibt einen Wert ungleich Null zurück, wenn das Dialog-Gadget erfolgreich erstellt wurde; andernfalls
  wird Null zurückgegeben. Um weitere Informationen zu einem aufgetretenen Fehler zu erhalten,
  verwenden Sie @@DialogError.

@Remarks
  Die Größenänderung des erstellten Gadgets (zum Beispiel mittels @@ResizeGadget oder durch die eigene
  Größenänderungs-Behandlung des Host-Fensters) führt automatisch zu einer Neuanordnung seiner
  untergeordneten Elemente, sodass diese an die neue Größe angepasst werden – genau wie bei einem
  Dialogfenster, das mit @@OpenXMLDialog geöffnet wurde.

@Example

@Code
  #Dialog = 0
  #Xml = 0
  #Window = 0

  XML$ = "<window name='test'>" +
         "  <vbox expand='item:3'>" +
         "    <string name='name' text='Your name' />" +
         "    <checkbox name='newsletter' text='Subscribe to the newsletter' />" +
         "    <editor name='comment' height='80' />" +
         "  </vbox>" +
         "</window>"

  If OpenWindow(#Window, 0, 0, 320, 240, "XmlDialogGadget", #PB_Window_ScreenCentered | #PB_Window_SystemMenu | #PB_Window_SizeGadget)

    TextGadget(#PB_Any, 10, 10, 300, 20, "This window hosts a dialog defined in XML:")

    If ParseXML(#Xml, XML$) And XMLStatus(#Xml) = #PB_XML_Success

      If CreateDialog(#Dialog) And XmlDialogGadget(#Dialog, #Xml, "test", 10, 35, 300, 160)

        ; Das Dialog-Container-Gadget selbst wird über den Namen seines <window>-Root-Elements abgerufen
        Container = DialogGadget(#Dialog, "test")

        Ok = ButtonGadget(#PB_Any, 210, 205, 100, 25, "OK")

        Repeat
          Event = WaitWindowEvent()

          Select Event
            Case #PB_Event_SizeWindow
              ; Durch die Größenänderung des Containers werden die darin enthaltenen Dialog-Elemente automatisch neu angeordnet
              ResizeGadget(Container, #PB_Ignore, #PB_Ignore, WindowWidth(#Window) - 20, WindowHeight(#Window) - 80)
              ResizeGadget(Ok, WindowWidth(#Window) - 110, WindowHeight(#Window) - 35, #PB_Ignore, #PB_Ignore)

            Case #PB_Event_Gadget
              If EventGadget() = Ok
                Debug "Name: " + GetGadgetText(DialogGadget(#Dialog, "name"))
                Debug "Newsletter: " + GetGadgetState(DialogGadget(#Dialog, "newsletter"))
              EndIf
          EndSelect
        Until Event = #PB_Event_CloseWindow

      Else
        Debug "Dialog error: " + DialogError(#Dialog)
      EndIf
    Else
      Debug "XML error: " + XMLError(#Xml) + " (Line: " + XMLErrorLine(#Xml) + ")"
    EndIf
  EndIf
@EndCode

@SeeAlso
  @@OpenXMLDialog, @@DialogGadget, @@DialogWindow
