@Title Procedures

@Syntax

  @Keyword Procedure[.<type>] name(<parameter1[.<type>]> [, <parameter2[.<type>] [= DefaultValue]>, ...])
    ...
    [@Keyword ProcedureReturn value]
  @Keyword EndProcedure

@Description

  A @Keyword Procedure is a part of code independent from the main code which can have any parameters
  and its own @ReferenceLink "variables" "variables". In PureBasic, a recurrence is fully supported for the procedures
  and any procedure can call it itself. At each call of the procedure the variables inside
  will start with a value of 0 (null). To access main code variables, they have to be shared
  by using @ReferenceLink "Shared" Shared or @ReferenceLink "Global" Global keywords
  (see also the @ReferenceLink "Protected" Protected and @ReferenceLink "Static" Static keywords).
  @LineBreak
  @LineBreak
  The last parameters can have a default value (needs to be a constant
  expression), so if these parameters are omitted when the procedure is called, the default value will be used.
  @LineBreak
  @LineBreak
  @ReferenceLink "dim" "Arrays" can be passed as parameters using the @Keyword Array keyword,
  @ReferenceLink "newlist" "lists" using the @Keyword List keyword and @ReferenceLink "newmap" "maps" using the @Keyword Map keyword.
  @LineBreak
  @LineBreak
  A @ReferenceLink "structures" "structure" or an @ReferenceLink "interfaces" "interface" can be passed as parameter, by using it as the
  parameter type, without '*'. Such a parameter is a @Bold "reference": see @Bold "Structure and interface parameters" below.
  @LineBreak
  @LineBreak
  A procedure can return a value or a string if necessary. You have to set the type after @Keyword Procedure
  and use the @Keyword ProcedureReturn keyword at any moment inside the procedure.
  A call of @Keyword ProcedureReturn exits immediately the procedure, even when its called inside a loop.
  @LineBreak
  @Keyword ProcedureReturn can't be used to return an @ReferenceLink "dim" "array", @ReferenceLink "newlist" "list" or a @ReferenceLink "newmap" "map".
  For this purpose pass the array, the list or the map as parameter to the procedure.
  @LineBreak
  @LineBreak
  If no value is specified for @Keyword ProcedureReturn, the return value will be zero if the compiler uses the C backend and for all processors managed by PureBasic, 
  or the content of the 'eax' register in 32 bits (X86 processors) or 'rax' in 64 bits (X64 processors) if the compiler uses the ASM back-end, 
  (see @ReferenceLink "inlinedasm" for more information).
  @LineBreak
  @LineBreak
  Note: To return strings from DLLs, see @ReferenceLink "DLL" DLLs. For advanced programmers @Keyword ProcedureC is available
  and will declare the procedure using 'CDecl' instead of 'StandardCall' calling convention. For more information on library
  calling standards (cdecl, stdcall, fastcall), see @InternetLink "https://en.wikipedia.org/wiki/Calling_convention" "here".
  @LineBreak
  @LineBreak
  Selected procedures can be executed asynchronously to the main program by using of @LibraryLink "thread" "threads".


  @Example Procedure with a numeric variable as return-value

@Code
  Procedure Maximum(nb1, nb2)
    If nb1 > nb2
      Result = nb1
    Else
      Result = nb2
    Endif

    ProcedureReturn Result
  EndProcedure

  Result = Maximum(15, 30)
  Debug Result
@EndCode


  @Example Procedure with a string as return-value

@Code
  Procedure.s Attach(String1$, String2$)
    ProcedureReturn String1$+" "+String2$
  EndProcedure

  Result$ = Attach("PureBasic", "Coder")
  Debug Result$
@EndCode


  @Example Parameter with default value

@Code
  Procedure a(a, b, c=2)
    Debug c
  EndProcedure

  a(10, 12)      ; 2 will be used as default value for 3rd parameter
  a(10, 12, 15)
@EndCode

 @Example List as parameter

@Code
  NewList Test.Point()

  AddElement(Test())
  Test()\x = 1
  AddElement(Test())
  Test()\x = 2

  Procedure DebugList(c.l, List ParameterList.Point())

    AddElement(ParameterList())
    ParameterList()\x = 3

    ForEach ParameterList()
      MessageRequester("List", Str(ParameterList()\x))
    Next

  EndProcedure

  DebugList(10, Test())
@EndCode

  @Example Array as parameter

@Code
  Dim Table.Point(10, 15)

  Table(0,0)\x = 1
  Table(1,0)\x = 2

  Procedure TestIt(c.l, Array ParameterTable.Point(2))  ; The table support 2 dimensions

    ParameterTable(1, 2)\x = 3
    ParameterTable(2, 2)\x = 4

  EndProcedure

  TestIt(10, Table())

  MessageRequester("Table", Str(Table(1, 2)\x))
@EndCode

@Example Static, dynamic array and passing a Structure to a Procedure
@Code
  Structure Whatever
    a.l
    b.l[2]          ; Static array (Standard C) with 2 values b[0] and b[1], not resizable
    Array c.l(3,3)  ; Dynamic array with 16 values c(0,0) to c(3,3), resizable with ReDim()
  EndStructure

  MyVar.Whatever

  Procedure MyProcedure(*blahblah.Whatever)
    *blahblah\a = 5
    *blahblah\b[0] = 1
    *blahblah\b[1] = 2
    *blahblah\c(3,3) = 33
  EndProcedure

  MyProcedure(@MyVar)
  Debug MyVar\a
  Debug MyVar\b[0]
  Debug MyVar\b[1]
  Debug MyVar\c(3,3)
@EndCode

@Bold "Structure and interface parameters"
@LineBreak
@LineBreak
When the type of a parameter is a structure or an interface, and its name doesn't begin with '*', the parameter is a reference.
The type of the passed value is checked by the compiler: it has to be of the same structure (or interface), or of one which
@Keyword Extends it, directly or not. The opposite isn't allowed: a parent can't be passed where a child is expected.
Two different structures don't match, even if they have the same fields.
The same applies to interfaces, even if they have the same methods. For example, a COM interface declared by your program can only be
passed where IUnknown is expected if it @Keyword Extends IUnknown (the interfaces provided by PureBasic already do).
@LineBreak
@LineBreak
The passed value can be a variable, an @ReferenceLink "dim" "array", @ReferenceLink "newlist" "list" or @ReferenceLink "newmap" "map"
element, a structure field, another reference parameter, or a typed @ReferenceLink "memory" "pointer" (*Pointer.Structure).
Other values, like 0, an address got with '@', a number, an untyped pointer or the result of an expression, are refused by the compiler.
A value returned by a procedure or a method has to be stored in a typed variable first.
@LineBreak
@LineBreak
With a structure parameter, the procedure works directly on the passed structure: no copy is done, so any change is visible by the caller.
It is used like a structured variable: Parameter\Field to access a field, the '@' operator to get the address of the structure, and
@ReferenceLink "compilerfunctions" "SizeOf" returns the structure size. Writing 'Parameter = OtherStructure' copies the content
of the other structure into the passed one. If the passed structure extends the parameter one, only the fields of the parameter
structure are changed.
@LineBreak
@LineBreak
An interface parameter is used to call the methods of the passed object. It can't be modified in the procedure, but it can be
copied to another variable.
@LineBreak
@LineBreak
A reference parameter is expected to always refer to an existing structure or object. A typed pointer or an interface variable can
still be null when the program runs: it is reported by the @ReferenceLink "debugger" "debugger" when it is passed to a reference
parameter. This check isn't done without the debugger.
@LineBreak
@LineBreak
When a parameter name begins with '*' (*Parameter.Structure), it is a regular @ReferenceLink "memory" "pointer": its type isn't
checked, it can be null, and the address of a structure has to be passed using the '@' operator.
@LineBreak
@LineBreak
A reference parameter can't have a default value, and @Keyword Declare has to use the same references as the @Keyword Procedure.
References can also be used in @ReferenceLink "prototypes" "Prototype" and @ReferenceLink "interfaces" "Interface" declarations.
They aren't supported in @ReferenceLink "import_endimport" "Import" declarations, nor in the procedures exported by a PureLibrary.
@LineBreak
@LineBreak
Arrays, lists and maps of structures passed with the @Keyword Array, @Keyword List and @Keyword Map keywords have to use
exactly the same structure.
@LineBreak
@LineBreak
Note: before PureBasic 6.60, an interface parameter without '*' accepted any value, which wasn't checked. To keep this behaviour,
add a '*' to the parameter name (*Object.IUnknown instead of Object.IUnknown) in the declaration and in the procedure code.

  @Example Structure as parameter

@Code
  Structure Shape
    Name$
    X.l
    Y.l
  EndStructure

  Structure Circle Extends Shape
    Radius.l
  EndStructure

  Procedure Move(Object.Shape, OffsetX, OffsetY)
    Object\X + OffsetX
    Object\Y + OffsetY
  EndProcedure

  MyCircle.Circle\Name$ = "Circle"
  Move(MyCircle, 10, 20)     ; 'Circle' extends 'Shape', so it can be passed
  Debug MyCircle\X          ; will print 10

  NewList Shapes.Shape()
  AddElement(Shapes())
  Move(Shapes(), 5, 5)       ; the list element is modified
  Debug Shapes()\Y          ; will print 5

  *Pointer.Shape = @MyCircle
  Move(*Pointer, 1, 1)       ; a typed pointer can be passed
  Debug MyCircle\X          ; will print 11
@EndCode

  @Example Interface as parameter

@Code
  Interface Animal
    GetLegs()
  EndInterface

  Interface Dog Extends Animal
    GetName.s()
  EndInterface

  Structure DogObject
    *VirtualTable
  EndStructure

  Procedure GetLegs(*This.DogObject)
    ProcedureReturn 4
  EndProcedure

  Procedure.s GetName(*This.DogObject)
    ProcedureReturn "Rex"
  EndProcedure

  Procedure ShowLegs(Object.Animal)
    Debug Object\GetLegs()
  EndProcedure

  MyObject.DogObject\VirtualTable = ?DogMethods
  MyDog.Dog = @MyObject

  ShowLegs(MyDog)            ; 'Dog' extends 'Animal', so it can be passed

  DataSection
    DogMethods:
    Data.i @GetLegs(), @GetName()
  EndDataSection
@EndCode


@Example Call a function by its name

@Code
   Prototype Function()

  Runtime Procedure Function1()
      Debug "I call Function1 by its name"
  EndProcedure

  Procedure LaunchProcedure(Name.s)
      Protected ProcedureName.Function = GetRuntimeInteger(Name + "()")
      ProcedureName()
  EndProcedure

  LaunchProcedure("Function1") ; Display "I call Function1 by its name"
@EndCode

@Syntax

  @Keyword Declare[.<type>] name(<parameter1[.<type>]> [, <parameter2[.<type>] [= DefaultValue]>, ...])

@Description

  Sometimes a procedure need to call another procedure which isn't declared before its definition.
  This is annoying because the compiler will complain 'Procedure <name> not found'. @Keyword Declare can help
  in this particular case by declaring only the header of the procedure. Nevertheless, the @Keyword Declare
  and real @Keyword Procedure declaration must be identical (including the correct type and optional parameters, if any).
  @LineBreak
  @LineBreak
  For advanced programmers @Keyword DeclareC is available and will declare the procedure using 'CDecl'
  instead of 'StandardCall' calling convention.

  @Example

@Code
  Declare Maximum(Value1, Value2)

  Procedure Operate(Value)
    Maximum(10, 2)      ; At this time, Maximum() is unknown.
  EndProcedure

  Procedure Maximum(Value1, Value2)
    ProcedureReturn 0
  EndProcedure
@EndCode
